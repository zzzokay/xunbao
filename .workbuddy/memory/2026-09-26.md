## 2026-09-26（续 12：OCR/数字「接受逻辑」审查 —— 找到 USART6 接收永久停摆的真机制）

**用户问**：识别数字时的接受逻辑有没有问题？为什么有时候摄像头一直在发、小车没反应？（**本轮只读不改**）

**⭐ 主因（可证，非推测）：`USART6_IRQHandler` 的"再武装"会被跳过 ⇒ 接收永久停摆**
- 接收是**单字节中断**：`Maxicam_Enable()` → `HAL_UART_Receive_IT(&huart6,&Maxicam_Rx,1)`。
- HAL 的 `UART_RxISR_8BIT`（`stm32f7xx_hal_uart.c:3922`）在收满 1 字节后**自己关掉接收**：
  `CLEAR(RXNEIE|PEIE)`、`CLEAR(CR3.EIE)`、`RxState=READY`、**`RxISR=NULL`**，只调空弱回调。
  ⇒ **必须有外部再调一次 `HAL_UART_Receive_IT` 才收得到下一个字节。**
- 全工程只两处会调：启动时的 `Maxicam_Enable()`，和 `Core/Src/stm32f7xx_it.c:465` 那句
  `if (HAL_UART_GetState(&huart6) == HAL_UART_STATE_READY) { 解析; Receive_IT; }`。
- `HAL_UART_GetState()`（`:2870`）= `gState | RxState` ⇒ **只要此刻正在发送（`gState=BUSY_TX`），条件为假，整段跳过**：
  该字节不解析、**且不再武装** ⇒ 之后 RXNEIE 关着、RxISR=NULL ⇒ **不再产生任何接收中断**，
  连 ORE 都没有（中断根本没开）⇒ **USART6 接收彻底停摆直到复位**，串口一个字都没有。
- 触发源全是 `huart6` 上的阻塞发送，**都在任务里调用**：`open_QR_mode()`(0x11)、`open_OCR_mode()`(0x22)、
  `close_Maxicam()`(0x66×4)。`WaitFor_OCR` 每轮开头 open、每轮失败 close，6 轮≈几十次发送，
  **偏偏这时摄像头在 OCR 模式全速吐数据** ⇒ 115200(87µs/字节) × 相机 ~100B/s ⇒ 每次 WaitFor_OCR 命中概率 ~10~30% ⇒ 正是"有时候"。
- 次生：`Process_QR_Data`/`Process_COLOR_Data` **在中断里**调 `close_Maxicam()` 做阻塞发送（OCR 那行已注释掉，是对的）。
- **全工程无 `HAL_UART_ErrorCallback` 实现**（只有 HAL 弱符号；`USMAT/uart.c` 那个只管 USART1）⇒ ORE/FE/NE 也无痕，
  且 ORE 走 `UART_EndRxTransfer()` 同样**关 RXNEIE + RxISR=NULL** ⇒ 同样依赖那句被跳过的再武装。

**建议修法（未做，待用户点头）**

2. 把 `Process_QR_Data`/`Process_COLOR_Data` 的 `close_Maxicam()` 改成置标志、由任务去发（ISR 内零阻塞发送）。
3. 兜底自愈：`WaitFor_OCR`/`WaitFor_QR` 每轮发指令**之前**，若 `huart6.RxState != BUSY_RX` 就补一次 `Receive_IT`。
4. 加痕迹：跳过分支打 `[MAXICAM] rx rearm skipped`。

**接受逻辑本身的 3 个静默丢弃点（同一处代码）**

**用户追问「什么情况会永久关闭接收 / 没有重试的时候重启吗」→ 补齐三点粒度（仍只读）**

**⭐ 关键实现细节（省事的那个）**：`HAL_UART_Receive_IT` **自身幂等** ——
入口 `if (huart->RxState == HAL_UART_STATE_READY) {…} else { return HAL_BUSY; }`（`stm32f7xx_hal_uart.c:1322`）。
⇒ **不需要包装函数、不需要自己判 `RxState`、不需要改头文件**，直接在发送点旁边裸调一句即可；返回 `HAL_BUSY` 时**不丢字节**（说明已有人武装）。

**⚠️ 放置陷阱（必须按这个放，否则白改）**：必须在**发送之后**补装（或下一轮循环体开头），
**写在 `while(retry--)` 外面/发送之前是无效的** —— 第一次发送期间那次锁死就没人治，后面两次 send 不会自己把中断开回来。

**B 治不了的两点（要如实告诉用户）**
