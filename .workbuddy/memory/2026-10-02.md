## 编辑器新增「路口判断标志位（DLEFT/DRIGHT）」一键校验/修复【仅上位机】

- **语义澄清（关键）**：DLEFT/DRIGHT 本质是「到达路口时车头哪一侧压横线」，由**路口几何形状**决定，与车「往哪转」无关（用户澄清）。
  - 方向映射（用边表 `angle` 自洽方向场 + 交叉积全量验证）：`need2turn(入边角, 出边角) > 0` = 左拐 = 车头左侧横线 = 需 DLEFT；`< 0` = 右拐 = 需 DRIGHT。
  - 折返（≈180°，平台/景点内部转身）不算路口横线，排除。
- **map_model.py 新增纯函数**：`junction_turns()` / `junction_flags_needed()` / `analyze_junction_flags(only_plain=)` / `suggest_junction_flags()` / `is_plain_edge()`；
  常量 `JUNCTION_RIGHT_ANGLE_TOL=20°`、`JUNCTION_UTURN_TOL=150°`、`JUNCTION_SPECIAL_FUNCS`（门/景点/跷跷板等特殊 func 集合）。
- **validate() 接入 warn 级报警**（多余/缺失），只查普通边 func=NONE。
- **UI 三按钮**（右栏「辅助」区新增 LabelFrame）：①按路口几何修 DLEFT/DRIGHT（选中/框选）；②按图上位置写好角度+路口标志（选中/框选）；③一键修复全图（弹确认框，只动普通边）。
- **测试**：`_selftest.py` 第 13 节 + `_guismoke.py` junction 段。全过（既有 `MAP_DEBUG` 干跑 FAIL 与本次无关）。
- 文档同步：README §9 日志 + PR §6/§9.5 + AI_CONTEXT §9。

### 复盘要点

## 路口判断升级为「多维分类器」（同日续）【仅上位机】

- **动机**：旧版只按「±90° 直角」二选一（`DLEFT`/`DRIGHT`），对斜岔路、大角度急弯等判不出来，用户要求分类型设计判断方式。
- **核心：`classify_turn_angle(d)`** 按岔线夹角 θ=|need2turn(入边角,出边角)| 分档，映射到灯位图案：
  - 直行/缓弯 θ≤20° → 无路口判据（岔线几乎与行进方向重合）
  - 斜岔路 20°<θ≤70° → `CLEFT`/`CRIGHT`（斜线点亮中段 2/3 灯）
  - 直角弯 70°<θ≤110° → `DLEFT`/`DRIGHT`（横线铺满半幅 6 灯）
  - 大角度急弯 110°<θ≤150° → `MCLEFT`/`MCRIGHT`（岔线靠外点最外侧单灯）
  - 折返 θ>150° → 排除（平台/景点内部转身不算路口）
- **线数类（MUL2SING/MUL2MUL）** 无法从单个角度反推，用**拓扑近似**：终点非折返出边 ≥3 条 → 多岔 MUL2MUL；≥2 条 → 汇入 MUL2SING。
- **分档阈值依据** = 边表真实转角分布聚类：0°(31 条直行)/90°(41 条直角主峰)/125~145°(19 条急弯)/30~70°(斜线散落)/15~25°(缓弯)。
- **`junction_flags_needed()` 返回 dict**{标志名:证据}（旧版返回 tuple `(need_dleft,need_dright)`）；`suggest_junction_flags()` 改为**重写全部 8 个到达判据位**（`JUNCTION_ARRIVE_FLAGS`），非到达位（RIGHT_LINE/STOPTURN/AWHITE 等）原样保留。
- **测试同步更新**：`_selftest.py` 第 13 节两处 tuple 断言改 dict 断言 + ⑥「保留其它位」改「到达位与几何一致」契约断言；`_guismoke.py` ③ 单选修复改「flag 与终点几何一致」（P3→N3 现在正确判出 CRIGHT+DRIGHT+MUL2MUL，不再等于旧的硬编码 `DRIGHT|RIGHT_LINE`）。
- 全过（`_selftest` 仅剩既有 `MAP_DEBUG` 干跑 FAIL，与本次无关）。
- 文档同步：README §9 加一行日志、PR §6 改写为分档表、PR §9.5 / AI_CONTEXT §9 更新函数清单与常量。

## 路口标志自动标注加「同时标 MUL 类」开关（同日再续）【仅上位机】

- **动机**：用户问"能否给线段关系自己标标志位"——能，但 MUL2SING/MUL2MUL 是**线数时序判据**（连续 >4 帧 `lineNum` 变化），静态只能拓扑近似、可靠性最低，不该跟角度类一样无差别自动写。用户选「改成可选开关」。
- **实现**：
  - `map_model.py` 三函数各加 `include_mul=True` 形参：`junction_flags_needed()` / `analyze_junction_flags()` / `suggest_junction_flags()`。默认 `True` 保持分析/校验全量口径；`False` 时不算不写 MUL2SING/MUL2MUL。
  - `map_editor.py`：`App.__init__` 加 `self.include_mul = tk.BooleanVar(False)`；「路口判断标志位」LabelFrame 顶部加 `Checkbutton`；三个入口方法 + `_apply_junction_flag_edits()` 透传 `include_mul=self.include_mul.get()`。
  - `validate()` 保持默认 `include_mul=True`（全量校验，与 UI 修复开关解耦）。
- **测试**：`_selftest` §13⑦ 加开关开/关两种断言（P3→N3 关=DRIGHT|CRIGHT|RIGHT_LINE、开=+MUL2MUL）；`_guismoke` junction 段加「开关默认关」断言 + ③b 开关关只标角度类。全过。
- 文档同步：PR §6/§9.5、README §9、AI_CONTEXT §9。

## 路口校验改「保守口径」（同日又续）【仅上位机】

- **触发**：用户反馈「地图明明能跑通，却报 50 条警告」。
- **根因**（重要，写进 PR §9.5）：多维分类器把 CLEFT/CRIGHT/MCLEFT/MCRIGHT（斜线/急弯精细分档）+ MUL（线数时序判据）都当"必须精确匹配"的硬判据，而固件作者手写时本就不精确，且 `deal_arrive()` 的 if 链优先级（`DLEFT→DRIGHT→CLEFT→…` 先命中生效）会覆盖它们 ⇒ 大面积假警告。
- **改法**：
  - `analyze_junction_flags()` / `suggest_junction_flags()` 各加 `right_only=False` 形参：`True` 时只检查/只重写 DLEFT/DRIGHT。
  - `validate()` 默认 `right_only=True + include_mul=False`：**只报 DLEFT/DRIGHT（直角左右）的确定性错误**。
  - `is_plain_edge()` 把带 `AWHITE`/`MUL*` 标志的边也当特殊边跳过（新增 `JUNCTION_SPECIAL_FLAGS`）——如 P6→N7 func=NONE 但带 AWHITE=门区检测，DLEFT|DRIGHT 是作者有意写双向检测，不该套直角弯。
- **效果**：51 条 → **8 条**；其中真正「左右写反」硬错仅 **2 条**（N12→N8、N16→N18）。
- **测试**：`_selftest` §13⑧ 加 right_only 断言（只报 DLEFT/DRIGHT + 仍能抓出 N16→N18 写反）。全过。
- ⚠️ 踩坑：`_guismoke` 的 `winfo_ismapped()` 断言在无头 Tk 下**偶发 flaky**（mapped=[False]），重跑即过，与逻辑无关——别被它误导。

## 路口检测补偿：第一性原理几何仿真可行性分析【仅文档+过程产物，未碰固件】

- **目标**：把「检测到路口 → 走到路口中心」的补偿从人工实测改为仿真计算。
- **物理模型**：循迹板 16 灯装车头（bit15=最左），旋转中心 O 在四轮几何中心（板后方 L）。
  引导线宽 3cm。检测瞬间板中心到路口中心纵向距离 s，补偿 Δ = s + L。
  灯 i 到出边线带符号距离 = s·sinφ + y_i·cosφ（解析式，非逐步仿真）。
- **关键区分**：补偿表分**停车原地转 stop（15 条生效）**与**陀螺不停车转 gyro（7 条生效）**，语义不同
  —— stop 是原地转（Δ=s+L 几何可算），gyro 是弧线转（需动态转弯半径 R，静态算不出）。
  之前误判 B2>N1>P1/B3>N2>P2 是死值，实际 flag 带 STOPTURN ⇒ 走 stop 生效。
- **拟合结果**：stop 分支 MAE≈4.15cm（15/15 成功）、比例系数 k≈0.908、线性回归斜率 0.95 截距−1.3（≈y=x 几乎不需缩放）。
  反解物理参数：**L=16cm、灯距 1cm、中心间隙 1.5cm、线半宽 2cm**（与文档 L 实测中位 16.7 吻合）。
  对比旧结论 LOO-MAE 7.2cm，几何仿真降到 4cm。
- **残差大的三条有物理原因**（对应文档 §14.2 崩掉的点）：`B9>N7>P6`（step=5 极短边，+24.9）、
  `N8>N5>N4`（门区 DOOR，−6.5）、`B3>N2>P2`（−30° 小角度 CLEFT，+7.1）。
- **过程产物**（`地图修改上位机/reports/`，可清空）：`sim_junction_detect.py`（几何仿真引擎）、
  `fit_junction_final.py`（stop 拟合）、`路口检测补偿_几何仿真可行性.md`（报告）、`junction_fit_final.json`。
- **落地建议**：把 Δ=s+L 写进 `GetForwardDistanceBeforeTurn()` 的 Tier2 替换 `L(1−cosφ)+d(判据)` 拟合式；
  已实测边仍走 Tier1（5cm 闸门）。gyro 分支需先标定转弯半径或保持实测。

## 路口检测补偿 —— 对账（回应"4.15cm 很大了"）

- **结论**：4.15cm 的 MAE 大头不是模型缺陷，而是 15 条实测值里混入 4 条**几何上不可算**的离群点，
  与 PR §14.2/§14.7 早已标注的"崩掉的点"逐一对应。
- **分组 MAE（s+L 仿真）**：可算平地大角度 6 条 = **2.38cm**；门区 DOOR 3 条 = 3.10；
  小角度 2 条 = 4.15；极短边 step<20 4 条 = 7.61（`B9>N7>P6` step=5 残差 +24.9 拉爆）。
- **4 个离群点**：`B9>N7>P6`(段长补偿)、`N8>N5>N4`(门区多判据)、`B3>N2>P2`(小角度低估)、
  `N4>N3>N8`(X交叉怪值)。这些都是"补偿值里混入了几何之外的信息"，仿真替代不了。
- **对比 PR 公式**：`L(1-cosφ)+d(判据)` 在可算条目上反而更差（`C4>N20>P8`+12.2、`B11>C4>N20`+19.0），
  因为它是给"没测过的边"兜底用的，对已实测条目本就该被 5cm 闸门挡回。**s+L 几何仿真完胜**。
- **落地**：只对"可算 6 条"用几何仿真（k≈0.9）；极短边/门区/小角度保留实测或单独补段长/横向偏置项。
  要再降误差只能量机械常数 L（~19cm，现拟合 16cm）与板半宽 w。
- **过程产物**（reports/，可清空）：`verify_geometric_model.py`、`verify_geometric_model.json`、
  `路口检测补偿_对账报告.html`。
