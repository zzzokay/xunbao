## 视觉串口（MaixCam/USART6）审查 + 一处无害修复
- **审查范围**：打开（`open_QR/OCR/COLOR` 0x11/0x22/0x33，带 0x94 确认 + `MAXICAM_OPEN_RETRY=3`）、关闭（`close_Maxicam` 发 4 次 0x66 不等确认）、接收（`USART6_IRQHandler` 单字节中断 → `Maxicam_ProcessRxByte` 状态机）、校验（帧头+ASCII+0x0A+连续 2 次相同+OCR 平台门控）、兜底（扫描循环 0.48s 重发保活 + 总超时）。
- **用户两个担忧的结论**：①打开——正常路径及时（进 while 第一拍 `timeout=0` 即 open），但 `open_*` 是阻塞 `HAL_Delay`（≤150ms）且失败静默、调用方不检查；②接收完退出——判定及时（2~3ms 拍），但识别结果若落在 `open_*` 阻塞窗口内会滞后最多 ~150ms（OCR 最明显：相机进模式后不再回 0x94 → 每次 `open_OCR_mode` 跑满 3 retry）。
- **本次唯一修复（低风险）**：`Core/Src/stm32f7xx_it.c` `USART6_IRQHandler` 去掉 `if(HAL_UART_GetState(&huart6)==HAL_UART_STATE_READY)` 门控，改为无条件 `Maxicam_ProcessRxByte` + `HAL_UART_Receive_IT`。根因：open/close 阻塞发送期间 `gState==BUSY_TX`，此时到达的字节被丢且接收中断不再重新挂载 → 偶发丢 0x94 确认/识别结果。改动在 `USER CODE BEGIN/END` 区间内，字节级替换，CRLF+UTF-8 保持，Keil 编译 **0 Error**（`compiling stm32f7xx_it.c` 确认重编译）。
- **未动（风险/收益不成比例）**：`open_*` 非阻塞化、假 ack（close 后 0x94 延迟到下次 open）、`close_Maxicam` 在 ISR 里阻塞发送、`K210.h` 死声明（`Maxicam_RxBytes`/`Maxicam_WaitWithResend`/`Reset_Process_State` 无定义）、`Open_COLOR_R` 无调用点。
