# scripts/map_editor/ — 地图图形化编辑器

> **一句话**：把固件里的地图（`Navigation/map.h` 的 `enum MapNode` + `Navigation/map_message.c`
> 的 `NavEdgeTbl[]`）画成一张可拖拽的图，改完直接导出成 C 代码 —— 不用再手抠 124 行边表。
> **只做辅助，不进固件**：`Navigation/`、`Mission/`、`Application/` 都不依赖它。

> 🤖 **给 AI / 接任者**：先读 **[AI_CONTEXT.md](AI_CONTEXT.md)**（架构、坐标系、必须保住的不变量、
> 安全规则与踩坑记录、常见改动指引）。本文件是**给人看**的使用说明。

---

## 1. 怎么跑

```bash
# 在仓库根执行（Tkinter 是 Python 自带，无需装任何东西）
python scripts/map_editor/map_editor.py
```

**更省事的办法：双击启动器**（在 `scripts/map_editor/` 目录里）
- `run_editor.bat` —— 双击就开，不弹命令行窗口
- `run_editor_console.bat` —— 带窗口版，出错时能看到报错（排查用）

打开就是**当前固件里的真实地图**，不是空图；有过保存的布局还会**自动载入**。

可选参数：
```bash
python scripts/map_editor/map_editor.py --bg 寻宝地图/场地规则图.png
python scripts/map_editor/map_editor.py --layout scripts/map_editor/layouts/default.json
```

依赖：Python 3（自带 tkinter）。换底图/用 jpg 需要 `pillow`（本机已装 12.3.0）：
```bash
pip install pillow
```

自检（不需要人看）：
```bash
python scripts/map_editor/_selftest.py     # 解析/往返/导出/编辑/规划，全过 exit 0
python scripts/map_editor/_guismoke.py     # 界面能建、能画、能选中、布局能存能读
```

## 2. ⭐ 最重要的两条心智模型

### 2.1 节点位置 = 示意图，与长度无关

图上的**远近只表示拓扑与角度关系，不代表实际距离**。
每条边的真实长度只看它自己的 **`step` 数值**（单位 cm）。

⇒ 所以：**拖动节点随便拖**，拖多远都不会影响任何 `step` / `angle` 数值，也不会影响固件行为。
拖动的唯一作用是让你自己看得清、让图贴合标准节点图。

（反例提醒：`B9→N7` 表里 `step=5`，但在节点图那段看起来很长 —— 这就是"图上距离不可信"
的典型。别用图上距离去推 `step`。）

### 2.2 拖动有约束：角度锁定 + 最小长度（可关）

按需求实现了**约束拖动**（工具栏，默认开启）：

| 控件 | 含义 |
|------|------|
| ☑ **锁角度** | 拖动节点时，它与相邻节点的方向被**吸附到该边表里 `angle` 所确定的直线**上（同一条线段两个方向都算合法）。角度**直接按数值**，不靠手拖。 |
| ☑ **限最小长度** | 该边图上长度必须 **≥ `step`(cm) × 单位长度 K**。不够就自动推出去。 |
| **单位长** `K` | 每 1 cm 对应多少图坐标单位（px）。**默认 0.884 px/cm，可以改**（就是你说的"要考研修改"的那个单位长度）。 |

拖动时画布上会实时显示：被拖节点每条相邻边的 **长度(px/cm) / step / 需≥多少**，
**绿色=合规、红色=违规**，状态栏同步给出文字读数；被吸附时提示"已吸附到合法位置"。

### 2.3 视图旋转 & 拖动引导线角度

**视图旋转**（工具栏「旋转」）：0°/90°/180°/270°，**节点和底图一起转**，纯显示。
**默认 0° = 不转，沿用 `节点图.jpg` 原本的角度**（已确认原图角度是对的）。
`SEED_POSITIONS` 已换算成**原图 1729×1080 像素坐标**，所以 0° 档下底图 1:1 铺开即贴合。

**拖动引导线角度偏移** `DRAG_ANGLE_OFFSET`（`map_editor.py` 顶部常量，默认 **90°**）：
表里 `angle` 与"引导线实际该指的方向"差 90°，所以约束用的方向按 `angle + 90°` 算。
想让引导线直接用表里 `angle`，把该常量改成 `0`。

> ⚠️ 已知副作用：同一条线段两个方向各自记了不同 angle，加 90° 后两者算出的引导线
> **不再共线**，于是某些"一个节点连着两条反向边"的节点（如 `S1↔N3`）会报
> 「引导线角度互相矛盾」。此时的行为是**放开不吸附**（节点照鼠标走，违规边标红），
> 不会出现"怎么拖都不动"的假死。

> 「屏幕上 0° 朝哪」在四个档位下依次是：0°→**上**、90°→**左**、180°→**下**、270°→**右**。

我实测过（`analyze_unit_length.py`）：`图上px ÷ step` 这个比值**从 0.17 到 94.9，差 500 倍**。
所以**不存在**一个 K 能让所有边都满足"长度 ≥ step×K"：

| K (px/cm) | 违反约束的边数 |
|---|---|
| 0.5 | 5 / 122 |
| **0.884**（默认） | **25 / 122** |
| 1.0 | 30 / 122 |
| 2.0 | 63 / 122 |

（典型：`C2→C1` 表里 step=185cm 但图上只有 32px；`B9→N7` 表里 5cm 但图上 87px。）

⇒ 因此：
- 工具栏「**违反约束的边**」会列出所有"本就不满足"的边，让你自己取舍 K；
- 这些边**本来就拖不出合法位置**，不是你操作错；
- 想要完全自由就关掉这两个勾。

#### 多边节点的角度约束可能"互斥"

一个节点连着 ≥3 条边、且它们方向不同时，**"所有边都严格保持角度"是无解的**
（例：`C9` 同时被 `N22`(-90°) 与 `G1`(180°) 要求两个方向）。
这时求解器会：① 优先找满足全部约束的最近点；② 真找不到就退化成"逐条边投影取最优"，
并**如实报「约束互斥」+ 逐条标红**，不会假装满足。

> 实现要点（将来改这块别踩）：角度判据用的是**点到直线距离**，不是"与某方向向量平行"——
> 因为同一条线段两个方向记的角度不同（`S1→N3=160°` / `N3→S1=-25°`），用方向叉积会把
> 正常情况误判成矛盾。另外射线候选点里**必须精确加入垂足**，否则单边节点会被弹到远处。

### 2.2 角度也只认数值，但图上相对走向可以帮你对数

`angle` 同样是数值。不过既然位置是照节点图摆的，**图上两点的相对走向**可以用来对照
表里的 `angle` 是否离谱（编辑器「辅助 → 按图上位置算角度」就是干这个的）。
再次强调：这只是**辅助核对**，最终真值靠实车标定。

## 3. 底图（节点图）对齐

启动时自动把 `寻宝地图/节点图.jpg` 作为半透明底图铺在下面，方便你一眼看出
"哪个节点画到哪儿去了、有没有画歪"。

### 3.1 换底图（可以用你自己画的图）

右栏「**底图对齐**」面板的下拉框会列出 `寻宝地图/` 下所有图片，点「浏览…」可以选
**任意目录的任意图片**（jpg 需要 pillow）。也可以用命令行：
```bash
python scripts/map_editor/map_editor.py --bg D:\我的图.png
```

### 3.2 对齐（三种办法，任选）

| 办法 | 操作 |
|------|------|
| 自动贴合（推荐先点） | 「**贴到节点**」= 拿"图上量过坐标的节点"做**最小二乘拟合**，自动算出最佳偏移/缩放 |
| 手动微调 | 「偏移 X / 偏移 Y / 缩放 X / 缩放 Y / 透明度」**滑条 + 数字框**：滑条快速拖，**数字框直接填精确值（可填负几千）** —— 滑条拖不准时用数字框 |
| 重新开始 | 「**居中**」= 回到 1:1 且与节点包围盒居中对齐 |

> 实测：用 48 个有图上坐标的节点反推，**平均残差只有 5.7 px**（原图 1729×1080），
> 说明节点坐标和原图基本是对齐的；剩下那几个对不上是因为**原图上根本没画它们**。
>
> ⚠️ 偏移量的滑条范围是 ±3000；**数字框没有范围限制**，摆不到位就用数字框。

### 3.3 ⚠️ 有 6 个节点原图上没有画

`C2 / B4 / C6 / C7 / C8 / G1` 在 `节点图.jpg` 上**没有对应的圆圈/方块**，
所以它们**怎么对都对不上**（坐标是按相邻节点+边表角度估的，见
`map_model.MISSING_SEED`）。按你觉得对的位置拖过去即可 —— 不影响任何数值。

### 3.4 对齐标定会存下来

标定（偏移/缩放/透明度/底图路径）会随「保存布局」一起写进 JSON，下次打开自动恢复。

> **对齐原理**：`SEED_POSITIONS` 就是这张 **1729×1080 原图的像素坐标**，
> 所以底图按 1:1 铺开即可对齐（不需要任何缩放换算）。已验证：`P8(96,510)` 与
> `N12(645,340)` 的像素差 549/170 与模型坐标差完全一致。
> 视图会按**节点包围盒**自动适配并居中，所以所有节点一定在视野里。

## 4. 操作速查

### 鼠标
| 操作 | 作用 |
|------|------|
| 左键拖节点 | 移动节点（只改示意图位置） |
| 左键点节点/边 | 选中，右侧「属性」面板改参数 |
| **Shift + 从节点拖出** | 拉一条新边，松手落在目标节点上 |
| 工具栏「连线模式」 | 等效于一直按住 Shift |
| 中键拖 / 空白处拖 | 平移画布 |
| 滚轮 | 以鼠标为中心缩放 |
| 双击空白 | 在该处新建节点 |
| 右键节点 | 连出新边 / 重命名 / 断开所有边 / 删除 / 设为必经点 |
| 右键边 | 编辑 / 补反向边 / 方向取反 / 删除 |
| 右键空白 | 新建节点 / 新建边 / 适配窗口 / 重新载入 |

### 键盘
`Ctrl+Z` 撤销 · `Ctrl+Y` 重做 · `Ctrl+S` **保存布局** · `Delete` 删除选中 · `F1` 帮助

### 工具栏（**分三行**）

一行放不下（加完旋转/吸附/长度/单位长之后总宽远超窗口，右侧控件会跑到屏幕外），故按语义分三行：

- **第 1 行（文件/编辑）**：重载源码 · 载入JSON · 保存布局 · 另存为 · 载入布局 ·
  撤销 / 重做 · ＋节点 / ＋边 / ＋双向边 / 删除选中 · 连线模式 / 双向
- **第 2 行（视图）**：网格 / 底图 / 换底图… · 标注档位 · 旋转 · 适配 / 校验 / 违反约束
- **第 3 行（拖动吸附 / 导出）**：**吸附模式** · **吸附阈值** · 限长度 · 单位长 K(px/cm) ·
  导出C代码 / 写回固件 / 帮助

> ⚠️ 改工具栏时注意：三行最宽约 1163px，窗口 `minsize` 为 **1200×720**。
> `_guismoke.py` 里有"至少三行且每行不溢出"的断言守着。

### 拖动吸附（默认「吸附水平/竖直」）

工具栏第 3 行的「吸附」下拉有三档：

| 模式 | 行为 |
|------|------|
| **吸附水平/竖直**（默认） | 按屏幕上的 **0°/90°/180°/−90°** 吸附：方向离某条轴 **≤ 阈值（默认 8°）→ 精确吸正**；≤ 软范围（25°）→ **拉到最近轴**；再远不干预 |
| 跟随角度表 | 方向偏好 = 边表 `angle + 90°`（旧行为，见 §2.3） |
| 自由 | 不做任何方向约束 |

配上「限长度」`|图上长度| ≥ step × 单位长K` 一起生效。拖动时画布上实时显示
每条相邻边的长度/step/是否已吸正，状态栏也会写"已吸正"。

> 默认选"吸附水平/竖直"是因为**节点图本来就不按角度表精确画**（图上方向与表里 angle
> 整体差 90°，见 §2.3），而且水平/竖直是人眼最容易对齐的参照。

## 4.5 布局的保存 / 另存为 / 多版本

**工具栏三个按钮：**

| 按钮 | 作用 |
|------|------|
| **保存布局** (`Ctrl+S`) | 存到 `layouts/default.json`，**下次启动自动载入** |
| **布局另存为** | 存成另一个名字（`layouts/` 下可放**多套**布局） |
| **载入布局** | 弹列表挑一个载入（最近的在上，含历史快照） |

**多版本保护**（因为曾经误删过用户布局，现在双层保险）：

- 每次「保存布局」若会覆盖已有文件，先把旧版复制成
  `layouts/snapshots/<名字>.<时间戳>.json`，**保留最近 30 份**；
- 「载入布局」列表里能直接看到 / 载入 / 删除这些快照。

**标题栏**显示当前布局文件名 + `*`（有未保存改动），避免"不知道在编辑哪一份"。

**布局文件里存了**：所有节点坐标 + 边表 + 底图路径与标定 + 拖动约束设置。

- 关窗口时若有未保存改动，会问「是/否/取消」；
- 「重新载入源码」（同步固件里新改的边表）**不会丢你拖好的位置**（按节点名搬过去）。

> 注意：**你保存的 `default.json` 优先级高于 `map_model.SEED_POSITIONS`**（启动自动载入布局）。

### 目录约定

```
scripts/map_editor/layouts/
  default.json              <- 「保存布局」目标，启动自动载入
  layout_0907_1530.json     <- 「布局另存为」存的多套布局
  snapshots/                <- 每次保存前的自动快照（保留最近 30 份）
    default.20260913_012033.json
```

命令行指定：`python scripts/map_editor/map_editor.py --layout <路径>.json`

### 分析你的布局

```bash
python scripts/map_editor/analyze_layout.py
```

输出：挪动过哪些节点、位置精度（对照图上实测地标）、单位长度 K 的建议与违规边、
按 `angle + DRAG_ANGLE_OFFSET` 判定的角度一致性、6 个"图上没画"节点的坐标。

## 4.6 测试为什么必须用沙箱目录（踩坑记录）

`_guismoke.py`（界面冒烟测试）**绝不允许碰 `layouts/*.json`**：

- 它用 `layouts/` 之外的工作区临时目录做保存 / 载入测试；
- 测试前后对真实布局做 **SHA256 比对**，不一致就直接 fail；
- 注意：沙箱目录必须用 `os.makedirs` 建，**不能用 `tempfile.mkdtemp`** ——
  本环境文件沙箱下 mkdtemp 建出的目录写入会 `PermissionError: [Errno 13]`（实测踩过）。

> 背景：曾有一个版本让测试脚本直接写 / 删真实 `default.json`，结果**误删了用户调好的布局**。
> 以后改 `_guismoke.py` 请务必保持这个隔离。

## 5. 三个面板

**左栏上 = 总览**：节点表（#序号 / 类型 / 出度入度）+ 边表。点一行＝选中并高亮。

### 边表的三种展示模式（「边显示」下拉框）

| 模式 | 行数 | 说明 |
|------|------|------|
| **合并双向**（默认） | 67（= 线段数） | **同一条线段的两个方向合成一行**，两个方向的「角度 / step」并列显示：`↔ A↔B  →角度 →step ←角度 ←step` |
| 逐条 | 124（= 边数） | 每行一条有向边，附加「功能」列，双向的标 `↔`、单向的标 `→` |
| 只看双向 | 114 | 只列出**有反向边**的那些（排查漏配的边很用） |

- 选中**合并行** → 选中正向边，属性面板标题会一并显示**反向边的参数**
  （`线段 A↔B 【反向边参数】B→A：xx° / step xx / func`）；
- 选中**单向边** → 标题提示 `⚠ 没有反向边`，可用属性面板的「补反向边」一键补上；
- 该模式会随「保存布局」记住。

> 实测：124 条边里 **114 条有反向边**，共 **67 条线段**（其中 57 条是双向的）。

**左栏下 = 路线规划**：把「起点 → 途径点 → 终点」依次加进必经点列表 → 「规划路线」。
用的是**与固件同一套 Dijkstra**（长度 + 转弯代价 `NAV_W_TURN=0.6` + 障碍惩罚
`NavObsPenalty[]`，`DOOR=60`/`BLBS=70`/`UpStage=60`）。结果会给出：
- 完整路线、`route[100]` 数组、每一段的 `角度/step/功能/flag`；
- ⚠️ 告警：**180° 原路折返**、**经过 DOOR 边**（`door()` 会清空 `route[]`）。

「读config」直接读 `Mission/config.h` 的 `FIRST_POINT/VIA_POINT/END_POINT`。

**右栏 = 属性 + 校验**：选中节点/边后在这里改 `from/to/flag/angle/step/speed/func/comment`。
- `angle` / `step` **可以直接写宏**（如 `ANGLE_N3N8`、`LEN_B7C6`、`DOOR_LEN_N3N8/2`），
  编辑器会按 `config.h` 当前 `USE_FIELD` 求值显示；
- flag 有 25 个位的勾选板，勾选自动拼成 `A|B|C`；
- 「辅助」里：按图上位置算角度 / 按图上位置算 step / 整条边取反 / 补反向边。

## 6. 导出 / 写回

### 6.1 导出 C 代码（只导出文本，不动源码）
工具栏「导出 C 代码」→ 分页：
- `NavEdgeTbl（整段）`：可直接整体替换 `map_message.c` 里那段的完整 C 文本；
- `边表表体（只粘表格）`：只含边行 + 分组注释；
- `enum MapNode`：按当前节点顺序重排的枚举；
- `NAV_EDGE_COUNT`；
- `求值自检`：每条边 `angle/step` 的实际求值结果（查宏有没有写错）。

可以「复制当前页」或「全部另存到目录…」（同时导出一份 `.json` 工程）。

### 6.2 写回固件（显式操作，会先备份）
工具栏「写回固件…」会把模型写回：
```
Navigation/map_message.c  <- NavEdgeTbl[]
Navigation/map.h          <- enum MapNode
Navigation/map_message.h  <- NAV_EDGE_COUNT
```
- **先自动备份**到 `scripts/map_editor/backups/<文件名>.<时间戳>.bak`；
- 有 `error` 级校验问题时**拒绝写回**；
- ⚠️ 写回后请 `git diff` 复核（本工程工作树常带未提交改动，见 project_reference §12.1）。

### 6.3 JSON 工程

## 7. 校验项

「校验」面板 / `do_validate()` 会查：
| 级别 | 内容 |
|------|------|
| error | `from/to` 不在 `enum MapNode` 里、自环、重复边 |

## 8. 回归保障（这个工具本身怎么保证不改坏东西）

- **往返一致**：不做任何编辑时，导出的边表与源文件**逐字段完全相同**
  （`_selftest.py` 第 2 节断言差异 0 处）。所以"打开→导出"不会引入意外改动。
- **宏求值 100%**：124 条边的 `angle/step` 全部能求值（含 `ANGLE_REV()` 派生宏、
  `LEN_N18B5 = (LEN_N22B7 - 20)` 这类带括号的表达式宏 —— 解析器特意处理了这两种坑）。
- `_selftest.py` 覆盖：解析 → 往返 → 宏 → 导出格式 → 编辑（增删改/改名/撤销）→ 规划 → 一次真实改动演练。
- `_guismoke.py` 覆盖：窗口构建、画布 item 数、树行数、选中、拖动、三档标注、
  校验面板、规划、各路导出、节点增删与恢复、滚轮缩放。

## 9. 已知限制 / 坑

1. **图上距离 ≠ 实际长度**（见 §2.1）。别用图反推 `step`。
2. **`C2/B4/C6/C7/C8/G1` 六个节点原图上没画**，坐标是估的（`MISSING_SEED`）——
   它们对不上底图是正常的，拖到你觉得对的位置即可。
3. **新增/删除节点后必须同步检查业务代码**：节点编号 = `enum MapNode` 顺序，
   `Mission/mission_planner.c` 的 `wp`、门逻辑、宝物表、`Mission/barrier.c` 里的
   节点比较都按节点名/编号走。编辑器只保证"导出文本正确"，不保证"业务还自洽"。
4. **底图会画到视野外**（它比节点范围大），属正常；适配是按节点包围盒算的。
5. 「用节点反推最佳位置」对**非等比例**的原图只能拟合出平均最优（残差会偏大）；
   这时改用滑条手调，或把 `缩放 X`/`缩放 Y` 调成不同值。
6. 写回固件后仍**必须**：跑 `scripts/validate/` 的 7 个脚本 → Keil V5.32 编译 0 error → 实车复核。
7. `S1 = 0`，而 `VIA_POINT=0` 是"不用途径点"哨兵 —— 所以 **S1 不能当途径点**（同 project_reference §9.6）。
