## 0. 5cm 闸门（安全线，已实现）

```
Tier1  表里（kTurnTbl[]）有这条三元组            → 用实测值
Tier2  规则命中 且 |公式 − 实测| ≤ 5cm           → 用公式
Tier3  其它                                     → 保持原默认 19
```

注意顺序：**先看表里有没有实测值，有就比对公式；差超过 5cm 就直接放弃公式、用实测值。**
这条闸门让整个机制**自保护**：以后每补一条实测数据，只要公式与它矛盾，就自动退回实测值——
可以放心地一条一条加数据，不会因为公式把这个点改坏。

被闸门挡回原值的 2 条：

|---|---|---|---|---|
| `C4→N20→P8` | 155° | 35 | 46.9 | +11.9 |
| `N4→N3→N8` | 145° | 20 | 29.1 | +9.1 |

> 原稿列的第三条 `N13→N18→B5`（60 vs 28.9）**是注释状态、根本不生效**，属于假警报，已剔除。

## 1. 判据：什么样的"能算"

三条同时满足才算（`Navigation/map.c` 的停车原地转分支）：

| 代号 | 条件 | 为什么 |
|---|---|---|
| **R1** | 入边 `func ∈ {NONE, DOOR}` | 传感器板还在**平地**上。跷跷板(QQB)/山(BHM/Hill)/桥(Bridge)/平台(UpStage/BLBS/BLBL/SM/BSoutPole…) 上板子离地或姿态改变，**检测时刻不可预测** |
| **R2** | 入边 `step ≥ 20cm` | `map.c` 的到达门槛是 `里程 ≥ 0.7×step`；`step≤18cm` 时只有 0.7~12.6cm，**车会被里程提前放行**，补偿实际在补段长，跟转弯几何无关 |
| **R3** | `100° ≤ |转弯| < 178°` | ① 小角度走"陀螺不停车转"分支，几何项 `1−cosφ` 太小（<0.1）② ≥178° 是原路折返，转身由平台函数/门逻辑处理，不该再加补偿 |

## 2. 公式与参数

```
Δ = L × (1 − cos φ) + d(判据)

L = 19.0 cm        ← "旋转中心 → 传感器板中心"的纵向距离（与现有默认值一致）
d(CRIGHT) = +11    ← 5 个样本
d(CLEFT)  =  −4    ← 4 个样本
d(DLEFT)  =  −5    ← 3 个样本
d(其他)   =  −4    ← 缺省
```

标定用的 8 条（平地 + `step≥20` + `100°≤φ<178°`）反解出的 `L`：**中位 16.7、均值 17.2、范围 11.0~24.4**，
子集内 `1−cosφ` 与实测值相关 **r = +0.71**。取 `L=19` 与现有默认值吻合。
（`d` 三个值不变 —— 那 8 条的判据分布与实测值都没被那条注释条目影响。）

## 7. 落地形态（✅ 已实现，实际代码见 `Navigation/map.c`）

实际实现与下面的草稿有三处不同，**以代码为准**：

1. **`kTurnTbl[]` 只有 13 条**（不是 16 条）：原表里 `B3→N2→P2`=24、`N8→N3→P3`=18 两条因进错分支永不生效，
   加上被注释掉的 `N13→N18→B5`=60 与无此边的 `N2→N8→N10`=15，共清掉 4 条。
2. **`func`/`step` 取的是"入边原始值"**（`Node_Lookup(last)`），**不是 `nodes.nowNode.step/function`** ——
   `door_set_pass_node()` 会在跑的过程中把 step 改成 72/50/36、function 改成 NONE。
3. 新增了 `static const NODE *Node_Lookup(u8)` 辅助函数；**不能拿 `getNextConnectNode()` 的返回值当
   `Node[]` 下标**（那是连接表偏移，只有恰好是第一个连接时才相等）。

```c
static const struct { u8 last, now, next; float dist; } kTurnTbl[] = {
	{ B9, N7, P6, 25 },  { P6, N7, B8, 20 },  { C4, N20, P8, 35 },
	{ N20, C4, B11, 25 },{ N3, N4, B2, 30 },  { P8, N20, C4, 30 },
	{ N8, N5, N4, 36 },  { N5, N8, N12, 20 }, { N8, N3, N4, 30 },
	{ N4, N3, N8, 20 },  { B8, N9, C3, 0 },   { N10, N9, B9, 48 },
	{ B2, N1, P1, 25 },
};

static float GetForwardDistanceBeforeTurn(u8 last, u8 now, u8 next)
{
    u8 found = 0; float meas = 19.0f;
    /* ... 查 kTurnTbl ... */
#if TURN_CALC_ENABLE
    {
        const NODE *in = Node_Lookup(last);          /* 入边原始属性，别读 nodes */
        float phi = fabsf(need2turn(nodes.nowNode.angle, nodes.nextNode.angle));
        if ((in->function == NONE || in->function == DOOR) && in->step >= 20 &&
            phi >= 100.0f && phi < 178.0f)
        {
            float d = TURN_D_DEFAULT;
            if      (arrive_method == ARRIVE_CRIGHT) d = TURN_D_CRIGHT;
            else if (arrive_method == ARRIVE_CLEFT)  d = TURN_D_CLEFT;
            else if (arrive_method == ARRIVE_DLEFT)  d = TURN_D_DLEFT;
            float calc = TURN_L_PIVOT * (1.0f - cosf(phi * (3.14159265f / 180.0f))) + d;
            if (!found || fabsf(calc - meas) <= TURN_GATE_CM) return calc;
        }
    }
#endif
    if (found) return meas;
    return 19;
}
```

> `arrive_method` 就是**节点检测判据的标志位**——Tier2 的最后一块拼图。
> `Task/ArriveDetect_task.c` 的 `deal_arrive()` 现在多一个 `uint8_t *out_method` 出参，
> 10 处 `return 1` 各自写入命中的判据，任务里再随 `CROSS_EVENT_ARRIVED` 交给 `Navigation()`。
> ⚠️ `barrier.c` 里有若干处**不经过 `deal_arrive` 就直接** `cross_event |= CROSS_EVENT_ARRIVED`，
> 那些情况下 `arrive_method` 会残留上一次的值 —— 公式会退回"缺省 d"，不会出错（但也不准）。
>
> **闸门是这套方案的关键**：有了它，以后每往 `kTurnTbl[]` 里加一条实测数据，
> 只要公式与它矛盾就自动退回实测值 —— 可以放心地一条一条加数据。

**陀螺不停车转那个函数（`GetForwardDistanceBeforeGyroTurn`）本次不动**——它 44 个组合里绝大多数是小角度，
现有表 + 默认 0 已经能用，而公式在小于 90° 时误差未经验证，动它风险大于收益。

## 8. 已知问题（下次维护必看）

1. **`map.h` 的节点编号与旧文档不一致**：`enum MapNode` 里 **`C1`/`C2` 是注释状态**，
   所以真实成员只有 50 个、`B11=49`（旧文档写 53）。解析枚举必须**先剥注释再编号**，
   否则从 `C3` 起全部错位。`project_reference.md §9.2` 已修正。
2. **分析脚本依赖"表在 `map.c` 里"这个事实**：本轮把 if 链改成 `kTurnTbl[]` 后，
   `analyze_turn_comp_base.py` 的解析器一度失效（还是去找 if 链）。已改成**同时认两种格式**。
   **以后再改表的结构，记得同步 `scripts/analyze/analyze_turn_comp_base.py`。**
3. **解析注释**：写这类"从源码抽表"的脚本时，务必用"剥注释后判断命中位置"的办法，
   而不是简单正则 —— 否则会把注释掉的条目当生效（本报告第一次的结论就是这么错的）。
4. **`N13→N18→B5`**：`kTurnTbl[]` 里**没有**这一条（原代码里它是注释状态）。如果实车发现这里确实需要补偿，
   加进表即可 —— 5cm 闸门会自动判断该用实测还是用公式。
5. **无法在 PC 上跑 ARM 代码**：本机没有主机 C 编译器、WSL 无发行版、`arm-none-eabi-gdb` 无 `target sim`。
   所以 `analyze_turn_comp_probe.py` 只做**保真性（可逆还原）+ 语法编译**校验，数值靠 python 侧同式独立计算。
