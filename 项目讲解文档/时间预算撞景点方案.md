# 时间预算撞景点方案（Time-Budget Gate）

> 状态：**待评审**（2026-10-11 起草）。实现前先确认「0. 待确认的规则点」。
> 依据：`比赛规则/规则文本_2026机器人寻宝.txt`——限时 180 秒；直立景点 11 分/个；
> 回家分 = 本次积分 20%（**要求访问 ≥3 个景点**）；总积分 A₁×30% + A₂×70%（二轮权重 70%）。

## 0. 待确认的规则点（实现前必须核对）

1. **"访问 ≥3 个景点"是否含平台景点**：按评分表口径，平台（1-6 号 30 分/个）与直立景点（11 分/个）都叫"景点"。
   一轮正常走完 = 平台A + 平台B + 宝物平台 = 已 ≥3 ⇒ 回家分资格大概率已满足，**撞直立景点不影响回家分资格**。
   若裁判口径"景点=仅直立景点"，则撞直立景点反而对回家分资格有贡献（撞 1 个不够，要 3 个）——决策逻辑要反过来。
2. **计时起点**：从"出发"（车动）起算 180 秒？还是从检录/开始键起算？影响计时器启动落点。
3. **两轮是否共用 180 秒**：规则"每轮比赛设两次出发机会"——若两轮各自 180s，则二轮需重置计时器（且二轮权重 70%，预算应更保守）。

## 1. 目标

在 180s 限时内最大化得分。优先级（按分值/耗时性价比）：

| 优先级 | 项 | 分值 | 额外耗时（估，待实测标定） |
|---|---|---|---|
| 0 | 回到出发平台 P2 | 本次积分 **20%**（估 200~400+） | 必需，不参与裁剪 |
| 1 | 补打卡 P3/P4 | 30 分/个 | P3 往返 566cm ≈ 20~25s；P4 已在回家必经路上（宝物=4 时增量≈0） |
| 2 | 直立景点 S1 | 11 分 | 往返 432cm + 175° 折返 ≈ 15~20s |
| 3 | 直立景点 S2 | 11 分 | 往返 240cm + 折返 ≈ 10~13s |

 ⇒ 时间不够时**裁剪顺序：S1 → S2 →（还不够再裁）P3 补打卡**；回家永远保留。

## 2. 计时器

- `Mission/config.h` 新增：
  ```c
  #define MATCH_TIME_LIMIT_S   180    /* 规则 2.1：180 秒 */
  #define TIME_RESERVE_S       10     /* 安全裕量：P2 上台阶 Stage_Home + 停稳判定 + 误差 */
  /* 以下为实测标定值（跑一次全程，按串口节点时间戳填） */
  #define COST_S1_TRIP_S       18     /* N3→S1→N3 往返含折返 */
  #define COST_S2_TRIP_S       12     /* N6→S2→N6 往返含折返 */
  #define COST_P3_TRIP_S       25     /* N3→P3→N3 含平台动作 */
  #define COST_HOME_PER_CM_MS  9      /* 回家耗时 ≈ 剩余路径 cm × 9ms/cm（实测标定） */
  #define COST_STAGE_HOME_S    8      /* P2 上台阶动作 */
  ```
- `Task/main_task.c`：开始键生效处（出发时刻）`match_start_tick = HAL_GetTick();`（`Mission/barrier.c` 或 map.c 定义 `uint32_t match_start_tick`）。
- 查询接口：`uint32_t Match_TimeLeft_S(void)` → `(MATCH_TIME_LIMIT_S*1000 - (HAL_GetTick()-match_start_tick)) / 1000`。
- 二轮：`get_newroute()` 入口重置 `match_start_tick`（若规则确认两轮各自计时；共用则不重置，改由 0.3 结论定）。

## 3. 决策落点（两级）

### 3.1 规划期粗决策（v1 必做，改动最小）

落点 = `mission_planner.c: append_round1_return_tail()`（宝物平台之后构造尾段的地方）。

改造：把"一次排完"改为"**逐项放行**"——沿沿途岔口顺序，每加一项前做预算检查：

```c
/* 剩余路径回家耗时（cm 从规划器拿：nav_plan_waypoints(当前->P2) 累计 step） */
static uint32_t round1_home_cost_cm(u8 from, const u8 *pending, uint8_t n);

for each 可选项 stop（按岔口顺序）:
    cost_with_stop  = home_cost(当前, [stop, 后续平台...], P2)   /* 规划器算 cm */
    cost_without    = home_cost(当前, [后续平台...], P2)
    if (Match_TimeLeft_S()*1000 - TIME_RESERVE_S*1000
            >= (cost_with_stop - cost_without) * COST_HOME_PER_CM_MS + stop_extra_s)
        wp[n++] = stop;     /* 装得下，保留 */
    else
        跳过;               /* 裁掉 */
```

要点：
- **决策发生在进 stub 边之前**（岔口处）。一旦上了 N3→S1 这条边就不许反悔（stub 内掉头会脱线）——粗决策天然满足。
- 宝物=4 的沿途序 `P4 → S2 → P3 → S1`：S1 最先被裁、S2 次之，与性价比一致。
- 裁掉景点**不裁补打卡平台**（30 分 > 11 分）；若连 P3 都装不下，只留 `…→P2`（此时回家分资格靠已访问的平台数撑着）。

### 3.2 运行期细决策（v2，防路途耽搁）

粗决策依据的是"规划那一刻"的剩余时间；去 P4 途中若堵转/重读门耗时超预期，预算会虚。v2 补一个复核点：

- 触发：一轮（`map.routetime==1`）**每次到达岔口节点并推进后**，若 route 前方含 View1 边（S1/S2）→ 复核预算；
- 不够 → 用 `nav_plan_waypoints({当前节点, [剩余平台], P2})` 重写 route（复用既有 `plan_route_at`），把景点裁掉；
- 触发点天然在岔口，满足"stub 内不可反悔"。

## 4. 上位机镜像与测试

- `map_model.py`：`round1_return_extra_waypoints()` 加 `time_left_s=None` 参数——None=不裁（现行为），数字=按预算裁，报告里每个被裁项标注「裁：剩余 XXs < 需 YYs」。
- `sim_route_bookkeeping.py`：Sim 加 `elapsed_s` 参数，run_case 覆盖三类边界（刚好够 / 差 1s / 明显不够）；红线加「超时仍绕景点 = 违规」检查。
- `_guismoke`：时间默认给足（不触发裁剪），既有断言不受影响。
- 实测标定：跑一次完整一轮，用串口时间戳（各节点 printf 加 tick）填 §2 的 4 个常数；再用「时间不够」场景实测一次裁剪生效。

## 6. 风险

- 常数不准 ⇒ 决策抖动（撞了一半时间没了）。缓解：TIME_RESERVE_S 取大（10s 起），v2 细决策兜底。
- 计时起点与裁判口径不一致 ⇒ 整体偏移。缓解：config 里加 `TIME_START_OFFSET_S` 微调。
- 二轮（A₂×70%）时间管理更值钱 ⇒ 若确认两轮各自计时，二轮 TIME_RESERVE_S 可放大（做成按 routetime 区分的宏）。
