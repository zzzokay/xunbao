# 地图修改上位机/map_editor/ — 地图图形化编辑器

> **一句话**：把固件里的地图（`Navigation/map.h` 的 `enum MapNode` + `Navigation/map_message.c`
> 的 `NavEdgeTbl[]`）画成一张可拖拽的图，改完直接导出成 C 代码 —— 不用再手抠 124 行边表。
> **只做辅助，不进固件**：`Navigation/`、`Mission/`、`Application/` 都不依赖它。

> 🤖 **给 AI / 接任者**：先读 **[AI_CONTEXT.md](AI_CONTEXT.md)**（架构、坐标系、必须保住的不变量、
> 安全规则与踩坑记录、常见改动指引）。本文件是**给人看**的使用说明。

---

## 1. 怎么跑

```bash
# 在仓库根执行（Tkinter 是 Python 自带，无需装任何东西）
python 地图修改上位机/map_editor/map_editor.py
```

**更省事的办法：双击启动器**（在 `地图修改上位机/map_editor/` 目录里）
- `run_editor.bat` —— 双击就开，不弹命令行窗口
- `run_editor_console.bat` —— 带窗口版，出错时能看到报错（排查用）

打开就是**当前固件里的真实地图**，不是空图；有过保存的布局还会**自动载入**。

> ⚠️ **但自动载入的布局会盖掉固件地图**（布局里连边表一起存）。如果那份 `default.json` 是旧的、
> 或存过试验性的改动（比如做过「切 C9-P7、加 C10」那种演示），那么**界面上显示的路线、校验结果、
> 导出的 C 代码全都基于布局，而不是车上的地图** —— 这是"上位机算的路线和车上不一致"的一个大来源。
> 现在启动时会自动比对并在**状态栏 + 「校验」面板**里告警，形如
> `⚠ 已自动载入布局，但它与固件源码不一致（＋1节点 / －0节点 / ＋4边 / －4边）`。
> 看到这条就点工具栏 **「重新载入源码」** 回到固件版（不会丢你拖好的位置）。

可选参数：
```bash
python 地图修改上位机/map_editor/map_editor.py --bg 寻宝地图/场地规则图.png
python 地图修改上位机/map_editor/map_editor.py --layout 地图修改上位机/map_editor/layouts/default.json
```

依赖：Python 3（自带 tkinter）。换底图/用 jpg 需要 `pillow`（本机已装 12.3.0）：
```bash
pip install pillow
```

自检（不需要人看）：
```bash
python 地图修改上位机/map_editor/_selftest.py     # 解析/往返/导出/编辑/规划，全过 exit 0
python 地图修改上位机/map_editor/_guismoke.py     # 界面能建、能画、能选中、布局能存能读
```

## 2. ⭐ 最重要的两条心智模型

### 2.1 节点位置 = 示意图，与长度无关

图上的**远近只表示拓扑与角度关系，不代表实际距离**。
每条边的真实长度只看它自己的 **`step` 数值**（单位 cm）。

⇒ 所以：**拖动节点随便拖**，拖多远都不会影响任何 `step` / `angle` 数值，也不会影响固件行为。
拖动的唯一作用是让你自己看得清、让图贴合标准节点图。

（反例提醒：`B9→N7` 表里 `step=5`，但在节点图那段看起来很长 —— 这就是"图上距离不可信"
的典型。别用图上距离去推 `step`。）

### 2.2 拖动有约束：角度锁定 + 最小长度（可关）

按需求实现了**约束拖动**（工具栏，默认开启）：

| 控件 | 含义 |
|------|------|
| ☑ **锁角度** | 拖动节点时，它与相邻节点的方向被**吸附到该边表里 `angle` 所确定的直线**上（同一条线段两个方向都算合法）。角度**直接按数值**，不靠手拖。 |
| ☑ **限最小长度** | 该边图上长度必须 **≥ `step`(cm) × 单位长度 K**。不够就自动推出去。 |
| **单位长** `K` | 每 1 cm 对应多少**图坐标**单位（px）。**默认 0.884 px/cm，可以改**（就是你说的"要考研修改"的那个单位长度）。 |

> **关于画布上的「图 xx.xcm」**（工具栏「边长(cm)」开关）：它是 **图坐标距离 ÷ K**，
> **与缩放无关** —— 放大缩小数字都不会变（曾用屏幕像素 ÷ K，导致数字随缩放变，已修）。
> 同一段用「辅助 → 按图上位置算 step」写进边表时也走同一个 K，不会再出现"标签一个值、
> 写进表另一个值"。

拖动时画布上会实时显示：被拖节点每条相邻边的 **长度(px/cm) / step / 需≥多少**，
**绿色=合规、红色=违规**，状态栏同步给出文字读数；被吸附时提示"已吸附到合法位置"。

### 2.3 视图旋转 & 拖动引导线角度

**视图旋转**（工具栏「旋转」）：0°/90°/180°/270°，**节点和底图一起转**，纯显示。
**默认 0° = 不转，沿用 `节点图.jpg` 原本的角度**（已确认原图角度是对的）。
`SEED_POSITIONS` 已换算成**原图 1729×1080 像素坐标**，所以 0° 档下底图 1:1 铺开即贴合。

**拖动引导线角度偏移** `DRAG_ANGLE_OFFSET`（`map_editor.py` 顶部常量，默认 **90°**）：
表里 `angle` 与"引导线实际该指的方向"差 90°，所以约束用的方向按 `angle + 90°` 算。
想让引导线直接用表里 `angle`，把该常量改成 `0`。

> ⚠️ 已知副作用：同一条线段两个方向各自记了不同 angle，加 90° 后两者算出的引导线
> **不再共线**，于是某些"一个节点连着两条反向边"的节点（如 `S1↔N3`）会报
> 「引导线角度互相矛盾」。此时的行为是**放开不吸附**（节点照鼠标走，违规边标红），
> 不会出现"怎么拖都不动"的假死。

> 「屏幕上 0° 朝哪」在四个档位下依次是：0°→**上**、90°→**左**、180°→**下**、270°→**右**。

我实测过（`analyze_unit_length.py`）：`图上px ÷ step` 这个比值**从 0.17 到 94.9，差 500 倍**。
所以**不存在**一个 K 能让所有边都满足"长度 ≥ step×K"：

| K (px/cm) | 违反约束的边数 |
|---|---|
| 0.5 | 5 / 122 |
| **0.884**（默认） | **25 / 122** |
| 1.0 | 30 / 122 |
| 2.0 | 63 / 122 |

（典型：`C2→C1` 表里 step=185cm 但图上只有 32px；`B9→N7` 表里 5cm 但图上 87px。）

⇒ 因此：
- 工具栏「**违反约束的边**」会列出所有"本就不满足"的边，让你自己取舍 K；
- 这些边**本来就拖不出合法位置**，不是你操作错；
- 想要完全自由就关掉这两个勾。

#### 多边节点的角度约束可能"互斥"

一个节点连着 ≥3 条边、且它们方向不同时，**"所有边都严格保持角度"是无解的**
（例：`C9` 同时被 `N22`(-90°) 与 `G1`(180°) 要求两个方向）。
这时求解器会：① 优先找满足全部约束的最近点；② 真找不到就退化成"逐条边投影取最优"，
并**如实报「约束互斥」+ 逐条标红**，不会假装满足。

> 实现要点（将来改这块别踩）：角度判据用的是**点到直线距离**，不是"与某方向向量平行"——
> 因为同一条线段两个方向记的角度不同（`S1→N3=160°` / `N3→S1=-25°`），用方向叉积会把
> 正常情况误判成矛盾。另外射线候选点里**必须精确加入垂足**，否则单边节点会被弹到远处。

### 2.2 角度也只认数值，但图上相对走向可以帮你对数

`angle` 同样是数值。不过既然位置是照节点图摆的，**图上两点的相对走向**可以用来对照
表里的 `angle` 是否离谱（编辑器「辅助 → 按图上位置算角度」就是干这个的）。

> ⚠️ **角度有两套约定，别混**：节点图坐标是**示意图**，图上"完全水平"的边在边表里应该写
> `0/180`，而图上"竖直"的边写 `±90` —— 直接用 `atan2` 算出来的裸几何角正好差 90°
> （实测本图 109 条边里 52 条是「几何 + 90°」、31 条是「几何 − 90°」，后者是同一根直线但方向相反）。
> 所以**新建边 / 「按图上位置算角度」**都走 `_auto_edge_angle()`：
> ① 起点已有**共线**出边（≤8°）→ 沿用它的 `angle`（地图自己的约定，最可靠）；
> ② 否则「几何 + `DRAG_ANGLE_OFFSET`(90°)」；③ 再把接近 `0/±90/180` 的值**吸附成整数**。
> 例：`C9→C10` 完全水平 ⇒ 算出 **180°**（反向 `0°`），不再是 88/90°。
> 框选多条一起重算时：**批内各边互不锚定**（只沿用**框外**共线边的角度），整批一个撤销点。
再次强调：这只是**辅助核对**，最终真值靠实车标定。

## 3. 底图（节点图）对齐

启动时自动把 `寻宝地图/节点图.jpg` 作为半透明底图铺在下面，方便你一眼看出
"哪个节点画到哪儿去了、有没有画歪"。

### 3.1 换底图（可以用你自己画的图）

右栏「**底图对齐**」面板的下拉框会列出 `寻宝地图/` 下所有图片，点「浏览…」可以选
**任意目录的任意图片**（jpg 需要 pillow）。也可以用命令行：
```bash
python 地图修改上位机/map_editor/map_editor.py --bg D:\我的图.png
```

### 3.2 对齐（三种办法，任选）

| 办法 | 操作 |
|------|------|
| 自动贴合（推荐先点） | 「**贴到节点**」= 拿"图上量过坐标的节点"做**最小二乘拟合**，自动算出最佳偏移/缩放 |
| 手动微调 | 「偏移 X / 偏移 Y / 缩放 X / 缩放 Y / 透明度」**滑条 + 数字框**：滑条快速拖，**数字框直接填精确值（可填负几千）** —— 滑条拖不准时用数字框 |
| 重新开始 | 「**居中**」= 回到 1:1 且与节点包围盒居中对齐 |

> 实测：用 48 个有图上坐标的节点反推，**平均残差只有 5.7 px**（原图 1729×1080），
> 说明节点坐标和原图基本是对齐的；剩下那几个对不上是因为**原图上根本没画它们**。
>
> ⚠️ 偏移量的滑条范围是 ±3000；**数字框没有范围限制**，摆不到位就用数字框。

### 3.3 ⚠️ 有 6 个节点原图上没有画

`C2 / B4 / C6 / C7 / C8 / G1` 在 `节点图.jpg` 上**没有对应的圆圈/方块**，
所以它们**怎么对都对不上**（坐标是按相邻节点+边表角度估的，见
`map_model.MISSING_SEED`）。按你觉得对的位置拖过去即可 —— 不影响任何数值。

### 3.4 对齐标定会存下来

标定（偏移/缩放/透明度/底图路径）会随「保存布局」一起写进 JSON，下次打开自动恢复。

> **对齐原理**：`SEED_POSITIONS` 就是这张 **1729×1080 原图的像素坐标**，
> 所以底图按 1:1 铺开即可对齐（不需要任何缩放换算）。已验证：`P8(96,510)` 与
> `N12(645,340)` 的像素差 549/170 与模型坐标差完全一致。
> 视图会按**节点包围盒**自动适配并居中，所以所有节点一定在视野里。

## 4. 操作速查

### 鼠标
| 操作 | 作用 |
|------|------|
| 左键拖节点 | 移动节点（只改示意图位置） |
| 左键点节点/边 | 选中，右侧「属性」面板改参数 |
| **双向边选方向** ⭐ | 两个方向的线现在**相隔 12px**：**偏向哪条就选哪条**；同一处**再点一次 = 切换方向**（状态栏会提示"同一处共 N 条"）。双击仍是"编辑当前选中那条"，不会被当成切换。<br>合并双向**边列表行**同理：再点同一行也在正/反方向间切换。 |
| **右键点节点** ⭐ | **以它为起点开始连线**；再右键另一个节点即成边（左键点目标也行） |
| **Shift + 右键点节点** | 节点快捷菜单：连出新边 / 重命名 / 断开所有边 / 删除 / 设为必经点 |
| **Shift + 从节点拖出** | 拉一条新边，松手落在目标节点上（备用方式） |
| 双击节点 | 同「右键点节点」（备用；原来只有这条路，左键双击经常点不中） |
| 工具栏「连线模式」 | 勾上后左键点两个节点也能建边；点边则以它的 to 端起继续连 |
| 中键拖 / 空白处拖 | 平移画布 |
| **Ctrl + 拖空白（框选）** ⭐ | 框一片区域：**节点**（拖动其中任一可整体移动）+ **边**（**两端节点都在框内**才算），选中变**紫色**。框选后「辅助 → 按图上位置算角度 / step」会**一次改所有选中的边**；点空白或点单条边则恢复单选。 |
| 滚轮 | 以鼠标为中心缩放 |
| Shift + 双击空白 | 在该处新建节点 |
| 右键边 | 编辑 / 补反向边 / 方向取反 / 删除 |
| 右键空白 | 新建节点 / 新建边 / 适配窗口 / 重新载入 |

> **连线怎么取消？** 再右键起点自己 / 点一下空白 / 按 `Esc`，都会放弃待连线的起点。
> **为什么改成右键**：原来"左键双击节点开始连线"经常点不中，一歪就变成选中/拖动/框选；
> 右键单击更稳。节点菜单的功能一个没少，只是挪到了 **Shift+右键**。

### 键盘
`Ctrl+Z` 撤销 · `Ctrl+Y` 重做 · `Ctrl+S` **保存布局** · `Delete` 删除选中 · `F1` 帮助

### 工具栏（**分三行**）

一行放不下（加完旋转/吸附/长度/单位长之后总宽远超窗口，右侧控件会跑到屏幕外），故按语义分三行：

- **第 1 行（文件/编辑）**：重载源码 · 载入JSON · 保存布局 · 另存为 · 载入布局 ·
  撤销 / 重做 · ＋节点 / ＋边 / ＋双向边 / 删除选中 · 连线模式 / 双向
- **第 2 行（视图）**：网格 / 底图 / 换底图… · 标注档位 · 旋转 · 适配 / 校验 / 违反约束
- **第 3 行（拖动吸附 / 导出）**：**吸附模式** · **吸附阈值** · 限长度 · 单位长 K(px/cm) ·
  导出C代码 / 写回固件 / 帮助

> ⚠️ 改工具栏时注意：三行最宽约 1163px，窗口 `minsize` 为 **1200×720**。
> `_guismoke.py` 里有"至少三行且每行不溢出"的断言守着。

### 拖动吸附（默认「吸附水平/竖直」）

工具栏第 3 行的「吸附」下拉有三档：

| 模式 | 行为 |
|------|------|
| **吸附水平/竖直**（默认） | 按屏幕上的 **0°/90°/180°/−90°** 吸附：方向离某条轴 **≤ 阈值（默认 8°）→ 精确吸正**；≤ 软范围（25°）→ **拉到最近轴**；再远不干预 |
| 跟随角度表 | 方向偏好 = 边表 `angle + 90°`（旧行为，见 §2.3） |
| 自由 | 不做任何方向约束 |

配上「限长度」`|图上长度| ≥ step × 单位长K` 一起生效。拖动时画布上实时显示
每条相邻边的长度/step/是否已吸正，状态栏也会写"已吸正"。

> 默认选"吸附水平/竖直"是因为**节点图本来就不按角度表精确画**（图上方向与表里 angle
> 整体差 90°，见 §2.3），而且水平/竖直是人眼最容易对齐的参照。

## 4.5 布局的保存 / 另存为 / 多版本

**工具栏三个按钮：**

| 按钮 | 作用 |
|------|------|
| **保存布局** (`Ctrl+S`) | 存到 `layouts/default.json`，**下次启动自动载入** |
| **布局另存为** | 存成另一个名字（`layouts/` 下可放**多套**布局） |
| **载入布局** | 弹列表挑一个载入（最近的在上，含历史快照） |

**多版本保护**（因为曾经误删过用户布局，现在双层保险）：

- 每次「保存布局」若会覆盖已有文件，先把旧版复制成
  `layouts/snapshots/<名字>.<时间戳>.json`，**保留最近 30 份**；
- 「载入布局」列表里能直接看到 / 载入 / 删除这些快照。

**标题栏**显示当前布局文件名 + `*`（有未保存改动），避免"不知道在编辑哪一份"。

**布局文件里存了**：所有节点坐标 + 边表 + 底图路径与标定 + 拖动约束设置。

- 关窗口时若有未保存改动，会问「是/否/取消」；
- 「重新载入源码」（同步固件里新改的边表）**不会丢你拖好的位置**（按节点名搬过去）。

> 注意：**你保存的 `default.json` 优先级高于 `map_model.SEED_POSITIONS`**（启动自动载入布局）。
> 它不只是坐标 —— **边表也一起存**，所以载入布局等于换了一张地图（见上方 ⚠️）。
> 想只用坐标、地图仍以固件为准：启动后点「**重新载入源码**」（按节点名保留你拖好的位置），
> 或者 `--layout` 指定另一份布局。

### 目录约定

```
地图修改上位机/map_editor/layouts/
  default.json              <- 「保存布局」目标，启动自动载入
  layout_0907_1530.json     <- 「布局另存为」存的多套布局
  snapshots/                <- 每次保存前的自动快照（保留最近 30 份）
    default.20260913_012033.json
```

命令行指定：`python 地图修改上位机/map_editor/map_editor.py --layout <路径>.json`

### 分析你的布局

```bash
python 地图修改上位机/map_editor/analyze_layout.py
```

输出：挪动过哪些节点、位置精度（对照图上实测地标）、单位长度 K 的建议与违规边、
按 `angle + DRAG_ANGLE_OFFSET` 判定的角度一致性、6 个"图上没画"节点的坐标。

## 4.6 测试为什么必须用沙箱目录（踩坑记录）

`_guismoke.py`（界面冒烟测试）**绝不允许碰 `layouts/*.json`**：

- 它用 `layouts/` 之外的工作区临时目录做保存 / 载入测试；
- 测试前后对真实布局做 **SHA256 比对**，不一致就直接 fail；
- 注意：沙箱目录必须用 `os.makedirs` 建，**不能用 `tempfile.mkdtemp`** ——
  本环境文件沙箱下 mkdtemp 建出的目录写入会 `PermissionError: [Errno 13]`（实测踩过）。

> 背景：曾有一个版本让测试脚本直接写 / 删真实 `default.json`，结果**误删了用户调好的布局**。
> 以后改 `_guismoke.py` 请务必保持这个隔离。

  ### 「第一轮·完整路线」是怎么拼的

  拼接点全部取自固件的真实交接点，不是猜的：

  1. `mapInit()` 把 `nowNode` 置成 `P2→N2`，之后 `route[] = nav_build_route({N2,P1,N5})`；
     在 P1 平台里 `update_route_at_P1()` 用手写数组**整条覆盖** `route[]`，而它的前 4 跳与
     `mapInit` 完全相同 ⇒ **完整路线 = `P2 → N2 → 手写数组`**。
  2. 三个手写数组一律以 `N12` 结尾（在 `N5→N12` 上读 D2）⇒ 门区从 `N12` 接着走，
     退回重读用 `door_read_hops()` 给出**真实边**序列（`N12→N8`、`N12→N8→N5→N4→N3→N8`）。
  3. `update_route_at_door_for_stageAB()` 的 `wp[0]` 就是过门落点 ⇒ 自然接上。
  4. 到第二个平台（P7/P8）读宝物 ⇒ `plan_treasure_return()` 的 `wp[0]` 就是该平台。
  5. 回程若穿过 **BACK 门**（`N10→N3` / `N8→N3`），`door()` 会再调 `route_return_home()`
     覆盖路线 ⇒ 再拼一段（`door_back_chain()` 负责这个分支链，含"退回 N8 再由 `N8→N3` 重读 D4"）。

  **画布**：去程画蓝色 `#1e88e5`、回程画青绿 `#00897b`，交接点（第二个平台）单独套一圈，
  并在路线包围盒左上角给图例（`去程 n 跳 / 回程 n 跳`）。回程起点 = 读宝物的那个平台。
  去程/回程叠在同一走廊看不清时，用左栏「**画布显示**」下拉只画一段（见上面「二轮路线…」前的说明）。

  「**二轮路线…**」的完整路线同样按这个规则分色：**去程 = 进门 + 整个巡游**，
  **回程 = 最后一个巡游平台 → P2**。


  > ⚠️ **门区最容易看错的就是"路线写在 `door()` 里面"**。`door()` 自己会做三件不改
  > `NavEdgeTbl[]` 却直接改路线/节点的事，编辑器以前完全不显示：
  > ① `door_retreat()` 后退并**隐式改 `nodes.nowNode`**（D2 黑退到 `N5→N8`、D3 黑退到 `N5→N4`、
  > D5 黑退到 `N10→N8`、D4 回程黑退到 `N8→N5`）；
  > ② D3 黑时 `load_route_at(0, door1route)` → **`route[] = {N3, N8}`**（去撞 D4）；
  > ③ D5 黑 + D2 蓝时 **`route[0]=N3; route[1]=0xFF`**（退回 N8 重读 D4）。
  > 「门区全流程」阶段把这些连同退回距离一起列出来，并会提示
  > **D5 非绿但 D2/D3 组合没有匹配分支** ⇒ `door()` 不置 `cross_event`
  > ⇒ 可能反复重读同一扇门（潜在死循环）。

  过门落在 N12 还是 N8 由 D2 能不能过自动推出（镜像 `door()` 把 `door_set_pass_node()`
  的返回值赋给 `nodes.nowNode`）。固件在这些输入下会 `CarBrake_Stop()` 的组合
  （如 D2/D3/D4 全黑）会**直接弹提示**，不会硬凑一条路线出来。

用的是**与固件同一套 Dijkstra**（长度 + 转弯代价 `NAV_W_TURN=0.6` + 障碍惩罚
`NavObsPenalty[]`）。结果会给出：
- 完整路线、`route[100]` 数组、每一段的 `角度/step/功能/flag`；
- ⚠️ 告警：**180° 原路折返**、**经过 DOOR 边**（`door()` 会清空 `route[]`）。

> ⚠️ **障碍惩罚表必须与固件 `Navigation/nav_planner.c` 的 `NavObsPenalty[]` 逐项一致**，
> 否则算出来的路线和车上跑的不是一条。历史上这里漏改过（`Bridge`/`Hill`/`LBHill`/`SM`/
> `View`/`View1`/`BACK`/`BSoutPole`/`QQB`/`BHM` 被写成 0、`BLBL` 写成 70）→ 规划器把桥、
> 山、楼梯、景点、跷跷板、波动板全当**免费捷径**。`_selftest.py` 第 8 节会解析固件源码
> **自动比对**，改了固件记得同步 `map_model.OBS`。
>
> 📌 **`Hill`（山地/楼梯）2026-09-13 由 300 降到 230**。为什么是 230 —— 各起终点对的翻转阈值不同：
> `N8→C9`/`N8→P5` 要 `Hill ≤ 239` 才走楼梯，而 `N12→N20` 要到 `≤200` 才走。取 230 就能让
> **「N8→C9 走楼梯、N12→N20 仍走南环」同时成立**，同时固件 15 条参考路线仍 15/15。
> 代价：`N12→P8`（阈值 247）等 **61/2450 对**会改走楼梯侧 → 需实车复核。
> ⚠️ 这个值写在**三个地方**：`nav_planner.c`、本工具的 `map_model.OBS`、`validate/_weight_calib.py`。

「读config」直接读 `Mission/config.h` 的 `FIRST_POINT/VIA_POINT/END_POINT`。

**右栏 = 属性 + 校验**：选中节点/边后在这里改 `from/to/flag/angle/step/speed/func/comment`。
- `angle` / `step` **可以直接写宏**（如 `ANGLE_N3N8`、`LEN_B7C6`、`DOOR_LEN_N3N8/2`），
  编辑器会按 `config.h` 当前 `USE_FIELD` 求值显示；
- flag 有 25 个位的勾选板，勾选自动拼成 `A|B|C`；
- 「辅助」里：按图上位置算角度（**走边表约定**，见 §5 的 ⚠️）/ 按图上位置算 step / 整条边取反 / 补反向边。
- **框选批量**：`Ctrl+拖空白`框选后，上面两个「按图上位置算…」按钮会一次改**所有选中的边**
  （判据：**两端节点都在框内**；紫色高亮）。整批**只记一个撤销点**（`Ctrl+Z` 一次全回退）；
  **批内各边互不做共线锚定**，只允许沿用**框外**共线边的角度 —— 否则改一条算一条时，
  先改的边会变成后改边的锚，结果依赖处理顺序；状态栏会报「几条沿用共线 / 几条按几何」。

### 平台快速交换（function 随平台切换）

**入口：左栏「边显示: [合并双向 ▾]」那一行的右边 —— 「⇄ 平台交换…」按钮。**
点开 → 选两个平台（P1~P8）→ 看**实时改动预览** → 「交换」。
（同一行右边还有「⟲ 转弯补偿…」，见本文下面那一节。）

**它只做一件事：把两个平台节点的名字互换。** 具体：

| 字段 | 怎么处理 |
|---|---|
| `from` / `to` | 互换（原来连 A 的边现在连 B，反之亦然） |
| **`step`（长度）/ `angle` / `flag` / `speed`** | **一个都不动** —— "长度还是原来的长度" |
| **`func`** | 换成"**新名字那个平台**"的入口/出口动作 ⇒ **function 随平台切换** |
| 图上坐标 | 默认**不动**（"其他沿用原来的"）；想连位置一起换就勾上那个勾选框 |

入口/出口动作是从**当前地图**读出来的（不硬编码）：P1/P3/P4/P5/P6 的进边是 `UpStage`、P2 是
`UpStageHome`、P7 是 `BSoutPole`、P8 是 `BHM`；出边照原样跟着走。

**例**（当前地图里 `P7` 连的是 `B7`）：

```
交换前：  B7→P7  step=10  func=BSoutPole      N13→P5  step=80  func=UpStage
交换 P5⇄P7 后：
          B7→P5  step=10  func=UpStage        ← 长度不变，function 变成 Stage
          N13→P7 step=80  func=BSoutPole      ← 长度不变，function 变回南极
```

> ⚠️ **换完请自己复核业务代码**：`Mission/mission_planner.c` 的 `wp`、门逻辑、宝物表，
> 以及 `Mission/barrier.c` 里按节点名做的判断，**全都按平台名字走**。编辑器只保证"边表/枚举正确"，
> 不保证业务自洽。对话框底部的橙字也在提醒这一点。
> 操作只是改内存模型（可 `Ctrl+Z` 撤销），**要点「写回固件」才会动源码**。

### 转弯前补偿（`map.c` 的两张硬编码表）

**入口：左栏「边显示:」那一行的右边 —— 「⟲ 转弯补偿…」按钮。**

固件里"转弯前补偿距离"**不在边表里**，而是 `Navigation/map.c` 的两张表：

| | 表 | 用在哪 |
|---|---|---|
| 表1 | `kTurnTbl[]` | **停车原地转**分支（走补偿距离 → 停车 → 原地转） |
| 表2 | `GetForwardDistanceBeforeGyroTurn()` 的 if 链 | **陀螺不停车转**分支 |

走哪个分支**不看表**，由 `map.c: Nav_TurnAndAdvance()` 的判据决定
（`|Δ| < 10°` 直行；`STOPTURN && |Δ| > 20°` 或 `|Δ| ≥ 90°` ⇒ 停车转；否则陀螺转）
⇒ 表里存着、但当前地图走不到那个分支的行就是**死值**，编辑器会标红。

对话框四个页签：

1. **① 停车原地转（kTurnTbl）** / **② 陀螺不停车转（if 链）**：可增删改
   （选中行 → 「改这一行」；**双击一行直接改值**），「状态」列实时告诉这一行
   **当前会不会生效**，`↑/↓` 调顺序。
2. **③ 覆盖总览**：地图里**所有** (入边, 出边) 转弯组合 + 当前实际生效的补偿值，
   来源分档 = 表1 实测 / Tier2 公式 / Tier3 默认 19 / 表2 实测 / 默认 0。
   勾「只看吃默认值」就能看到"还有哪些弯没数据"。
3. **④ 公式参数 / 开关**：`TURN_L_PIVOT`、`TURN_GATE_CM`、`TURN_D_*`（Tier2 "能算就算"），
   以及 `TURN_CALC_ENABLE`（在 `config.h`，有单独按钮只写回 config.h）。

点任一表的任一行 → **画布上把那个弯（上一步 → 当前 → 下一步）高亮出来**
（洋红折线 + 当前节点套圈 + 标转弯角）。

- **「写回 map.c…」**只改三处：表1 表体、表2 函数体、`kTurnTbl_node_check` 的节点号护栏
  （跟随表项重生成）；公式参数只改**真变了**的那个 `#define`（**行尾注释原样保留**）。
  写回前自动备份到 `backups/`。
- **没编辑过 ⇒ 一个字节都不动**：写回前先与源码逐项比对，一致就整段跳过，不会因为
  "缩进归一化"产生无意义 diff。**一旦编辑过**，整段表按统一格式重排（值不变）。
- 对话框不会自动写盘；关掉窗口只是取消高亮。

> ⚠️ **分支判定是"边表口径"的近似**：固件那条 `STOPTURN` 判据用的是**陀螺实测航向**
> `getAngleZ()`，静态算不出来 —— 所以"停车转"这一档里混着"还得陀螺也偏够"的那一支。
> 以实车 / 串口日志为准。
> ⚠️ 补偿值只由 **(上一步, 当前, 下一步) 三元组 + 入边属性**决定，与出边 `step` 无关；
> 而入边 `step` 太短的那一类补偿其实在**补段长**、跟几何没关系（`project_reference.md` §14.2）。
> ⚠️ **Tier2 的 d 取决于运行时 `arrive_method`**（由 `ArriveDetect_task.c` 写，
> 某些路径不经过 `deal_arrive()` 时会残留上一次的值）⇒ 覆盖总览里公式档给的是
> `值 min~max` 而不是一个确定数。

## 9. 已知限制 / 坑

1. **图上距离 ≠ 实际长度**（见 §2.1）。别用图反推 `step`。
2. **`C2/B4/C6/C7/C8/G1` 六个节点原图上没画**，坐标是估的（`MISSING_SEED`）——
   它们对不上底图是正常的，拖到你觉得对的位置即可。
3. **新增/删除节点后必须同步检查业务代码**：节点编号 = `enum MapNode` 顺序，
   `Mission/mission_planner.c` 的 `wp`、门逻辑、宝物表、`Mission/barrier.c` 里的
   节点比较都按节点名/编号走。编辑器只保证"导出文本正确"，不保证"业务还自洽"。
4. **底图会画到视野外**（它比节点范围大），属正常；适配是按节点包围盒算的。
5. 「用节点反推最佳位置」对**非等比例**的原图只能拟合出平均最优（残差会偏大）；
   这时改用滑条手调，或把 `缩放 X`/`缩放 Y` 调成不同值。
6. 写回固件后仍**必须**：跑 `地图修改上位机/validate/` 的 8 个脚本 → Keil V5.32 编译 0 error → 实车复核。
7. `S1 = 0`，而 `VIA_POINT=0` 是"不用途径点"哨兵 —— 所以 **S1 不能当途径点**（同 project_reference §9.6）。
