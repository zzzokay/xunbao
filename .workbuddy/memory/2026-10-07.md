## 修「上位机 群选拖动 / 单拖 都拖不动」【仅上位机，未碰固件源码】

- **用户报障**：Ctrl 框选能选出一堆紫色点，但拖动（群拖、单拖）全都不动。
- **根因**：`_on_node_press()` 第一行 `if connect_from or connect_mode: _connect_pick(name); return`
  ⇒ 工具栏**「连线模式」被无声打开**后，点节点变成"选连线起点"，拖不动；而 Ctrl+框选走
  `_on_bg_press` 的空白路径、**不查连线模式**，所以"框选照旧能选中"。
  连线模式很容易被无意打开：**双击任意节点**（`_on_node_double → start_connect_from`）、
  **按 `A` 键**（`bind_all("<Key-a>")`）、勾工具栏复选框。
  复现（确定性直调）：初始 `_drag` 就绪 → 双击节点后 `connect_mode=True` 且 `_drag=None` → Esc 后恢复。
- **改法（用户选"拖动优先"）**：`map_editor.py`
  - `_on_node_press`：不再被连线抢走，先装拖动状态；连线的落点从"按下"改到"**松手且没移动**"
    （`_on_release` 里 `if not moved and d.get("connect"): _connect_pick(d["name"])`）。
  - 新增模块常量 `DRAG_START_PX = 4`：`_on_motion` 里位移 ≤4px 不算拖动（抖动容忍，否则点击会变微拖）。
  - 新增 `_clear_stale_ptr_state()` + `_ev_token()`：残留 `_drag/_link/_marquee/_bg_drag`
    （松手时指针不在画布上 ⇒ 收不到 `<ButtonRelease-1>`）以前**空白点击也清不掉**，
    会永久废掉 Ctrl 框选 ⇒ 每次**新按下**先清。
- **⚠️ 本次自己踩的坑（已写进 README §3.4）**：本机 Tk 画布，节点 item 绑定返回 `"break"`

  原来那句 `if self._link or self._drag: return "break"` 正是靠它兜住刚装的状态。
  我先在 `_on_bg_press` 开头加自愈 ⇒ 把刚装的 `_drag` 当残留清掉，**直调处理函数的测试全过、
  真事件链全哑**。修法：同一次按下的 item/widget 绑定 `serial` 相同（实测都是 2405）⇒
  用 `_ev_token()` 比对，认出重复调用原样退回。`_Ev` 假事件没有 serial ⇒ token 为 None ⇒ 测试不受影响。
- **验证**：`_guismoke.py` 新增 4 组断言（拖动优先 / 抖动容忍 / 原地松手仍连线 / 残留自愈）
